How to change bot avatars for Hermes bots (Hermes on disk, part 1)

Published:   October 27, 2026

Tags:

How do you change bot avatars for Hermes bots on macOS? The short answer: Edit Profile, then Save. The long answer is why I needed two hours to learn that. I swapped 16 bot avatars in Hermes Bot Mode by putting new 512x512 PNGs on disk. The files were valid, and the app still showed the old faces after every restart. It turned out the avatar lives in three places, and the app trusted the one I wasn’t looking at.

Is this worth reading?

If you edit avatar files on disk, the desktop app can keep showing the old image because of its own cache. On macOS, Edit Profile, then Save is what worked for me. Below: where the three copies live, which one the app trusts, and the fix. Worth it if you manage more than a couple of bots. This is Part 1 of how Hermes keeps things on disk.

Quick steps (macOS)

  1. Easiest: Open the bot’s Edit Profile, set the image, and Save. That is what worked for me.
  2. Keep it under 2 MB (PNG, JPEG or WebP). I’d also use 512x512, not 160x160 (see below).
  3. Already changed files on disk? Clear the app’s cached copy (the fix below).

One home, two front ends (macOS)

By default, the Hermes desktop app and the hermes command line both use ~/.hermes. The app checks HERMES_HOME first, then falls back to that folder. A HERMES_HOME you set in your shell may not reach an app launched from the Dock or Finder. That is general macOS behaviour, not something we saw in Hermes. The app keeps its own choice of bot in ~/Library/Application Support/Hermes/active-profile.json and starts its backend with hermes --profile <name>. If that choice is unset, it uses the CLI’s ~/.hermes/active_profile. The two choice files are separate, so the app and the CLI can point at different bots. As far as the source comments show, the app runs the same hermes command as the CLI. Paths and behaviour come from Hermes Agent v0.22.5 (2026.9.24) and may change between releases.

Three copies of one avatar

From my debugging:

  1. Server copy: assets/avatar.png in the bot’s folder, served by the gateway through profiles.get_asset.
  2. Profile metadata: profile.yaml, under ui_meta.hermes-bots, holds the bot’s title and the image as a data URL. As far as I could tell, the gateway re-reads it on every roster poll.
  3. App cache: localStorage key hermes.plugin.hermes-bots.bot-meta-v2, in the app’s Local Storage/leveldb folder.

Copies 1 and 2 were correct; copy 3, the one the app paints from, still held the old images.

Why the cache never refreshed

In my build, the local image wins, and the app only asks the server when it has no local one. Simplified, from mergeServerMeta in profile-ops.ts:

// simplified
// server fields win...
const merged = { ...mine, ...server }
// ...except the image: local always wins
if (mine.image) { merged.image = mine.image }

These guards stop a roster refresh from wiping a fresh upload, but together they can make a correct backend change invisible, and restarting reloads the same localStorage.

The 160x160 trap: a PNG that is exactly 160x160 is treated as a backfilled auto-generated face (isBackfilledFacePng in avatar-image.ts), and pullServerAvatars skips it unless the bot’s saved image kind is already “photo”. This is PNG-specific, so I recommend 512x512; the only hard limit is 2 MB.

Why a file edit isn’t enough: profiles.set_asset (in methods_profiles.py) writes only assets/avatar.png, accepting PNG, JPEG or WebP up to 2 MB. It doesn’t touch the app’s cache, so a file-level change also needs that cache cleared.

Why it was hard to see

Every layer I could inspect looked fine, but this build didn’t expose a debugging port, so I read the source to see the cache. Two early restarts also didn’t take effect; I suspect the app was still shutting down when I relaunched it.

The fix (macOS)

  1. Quit Hermes fully and wait for it to exit.
  2. Back up the Local Storage/leveldb folder, then clear the hermes-bots.bot-meta* keys inside that folder.
  3. Relaunch. The app should re-pull the avatars from assets/avatar.png.

A caveat: I haven’t checked what else lives in those hermes-bots.bot-meta* keys. Deleting them may reset other app-side metadata for those bots, so back up first and try one bot before clearing all.

What I see on my Mac (Hermes Agent v0.22.5)

All paths in this post are for macOS. This is what I saw on my machine, not a spec:

  • App: /Applications/Hermes.app; CLI: ~/.local/bin/hermes
  • Hermes home: ~/.hermes, which holds the default profile (profile.yaml, config.yaml, state.db, kanban.db, skills/, memories/)
  • Bot profiles: ~/.hermes/profiles/<name>/, each with its own profile.yaml, SOUL.md, AGENTS.md, skills/, memories/, cron/, state.db and assets/avatar.png
  • App data (Electron): ~/Library/Application Support/Hermes/, with the renderer’s localStorage in Local Storage/leveldb inside it

Leave credential files in ~/.hermes alone; none of this needs them.

Takeaways

  • When one setting lives in three places, ask which copy the screen actually trusts.
  • Edit Profile, then Save is what worked for me. If you edited files directly, clear the app’s cache too.
